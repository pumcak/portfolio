Project 1.02 · Semester 1 · 2025-2026

Stock management tool in C

Context: Project 1.02 · Software development Duration: 1 month Team: Pair Stack: C · Algorithms

Context

Built in a pair, over one month, in the first semester of my first year on the BUT in Computer Science. The topic and the technical constraints were set by the lecturer, but the design and the organisation of the work were entirely down to us: we decided ourselves how to split the code into functions, what storage format to use and how to share out the tasks, with a weekly check-in with our supervisor.

This project mainly covers competencies C1 (Build an application) and C4 (Manage information and data).

Goal

Design a stock management tool in C to track items: adding, removing, editing, searching and displaying the inventory. What was expected was the program only: no graphical interface was required, and the marking was based on the correctness of the algorithms, how the code was structured and how reliably the data was saved.

Three constraints were imposed: procedural C (no objects), a command-line interface, and data saved to files, so no database.

What I did

I built a program structured around structs representing the items: reference, label, quantity and price. I implemented the main menu functions: adding an item, removing stock, updating quantities, searching by name or by reference, and displaying a sorted inventory. I also handled saving and loading the data from a file, along with validating user input and dealing with error cases.

Difficulties & what I learned

The main difficulty was handling memory and strings in C, along with reading from and writing to files reliably. I learned to split my code into clear functions, to test each module on its own and to anticipate invalid input. This project moved me forward on algorithmic rigour and on handling data structures.

Results

The deliverable is a working C program, with commented source code and a set of tests. The tool handles a full inventory from the start to the end of a session, with the data saved to a file. What I am proudest of: delivering a stable, readable and reusable program, my first real application of what I knew in C.

What I gained
  • A real understanding of pointers and memory, which was only a lecture concept before this project.
  • The habit of splitting code into short functions and testing each module on its own before integrating it.
  • Handling error cases and invalid input: the program we handed in did not crash on a single test scenario.
What I would do differently
  • I used a fixed-size array instead of dynamic allocation: easy to write, but the inventory is capped arbitrarily. Today I would go with a linked list.
  • The file format was homemade and fragile: one badly formed line broke loading. A standard format such as strict CSV would have avoided that.
  • We started coding too fast, with nothing drawn up first, which led to rewrites along the way. That is the lesson I applied on the very next project.
